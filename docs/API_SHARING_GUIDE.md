# Flood Risk Model API Sharing Guide

This document describes the Flask API that exposes the flood risk model and the commercial pricing logic for sharing with the dashboard/backend team.

## Purpose

The API provides:

- model outputs for a building or portfolio
- pricing inputs for the underwriter
- a transparent commercial quote breakdown
- the exact formula used for pricing

The dashboard team can call these endpoints and render the results in their own UI.

## How to run locally

From the project root:

```bash
source .venv/bin/activate
python -m src.api
```

By default the app runs on port `5000`.

If you want to share it with the team using ngrok:

```bash
ngrok http 5000
```

Share the ngrok forwarding URL with the team.

## Base URLs

- Local: `http://127.0.0.1:5000`
- Shared ngrok URL: generated by ngrok, for example `https://xxxx.ngrok-free.app`

## Open-source geocoding setup (optional)

For name-based quoting, the API can geocode a building name using Nominatim (OpenStreetMap).

Set these environment variables if needed:

- `GEOCODER_PROVIDER=nominatim`
- `GEOCODER_BASE_URL=https://nominatim.openstreetmap.org`
- `GEOCODER_USER_AGENT=bimasolutions-flood-model/1.0`

## Available endpoints

### `GET /health`
Checks that the API is running.

Response:

```json
{ "status": "ok" }
```

### `GET /formula`
Returns the pricing formula and assumptions.

Response fields:
- `pricing_formula`
- `assumptions`

### `GET /buildings`
Returns the model summary for all buildings.

Useful fields include:
- `building_id`
- `housing_class`
- `tiv_kes`
- `expected_annual_loss_kes`
- `aal_rate`
- `risk_score`
- `risk_class`
- `confidence`

### `GET /portfolio-summary`
Returns portfolio-level totals and headline model outputs.

### `GET /metrics`
Returns model metrics and validation outputs.

### `GET /quote/<building_id>`
Returns a commercial quote for one building using the stored model output.

Example:

```bash
curl http://127.0.0.1:5000/quote/NBO-0316
```

### `POST /quote`
Returns a quote from a JSON payload.

This endpoint supports three modes:

1. **Stored building mode**
   - send `building_id`
   - the API returns the quote from the portfolio

2. **Name-based mode (geocode + nearest portfolio match)**
   - send `building_name`
   - optional: `city`/`locality`, `country`
   - API geocodes the name and maps it to the nearest modeled building

3. **Freeform underwriter manual mode**
   - send `building_name`
   - also send the pricing inputs below
   - the building is not required to exist in the portfolio

Required fields by mode:
- Name-based mode: `building_name`
- Manual mode:
- `tiv_kes`
- `expected_annual_loss_kes`
- `risk_class`
- `confidence`

Example payload (name-based mode):

```json
{
  "building_name": "Landmark Plaza Commercial Development",
  "city": "Nairobi",
  "country": "Kenya"
}
```

Example payload (manual mode):

```json
{
  "building_name": "Landmark Plaza Commercial Development",
  "tiv_kes": 522650000,
  "expected_annual_loss_kes": 41030248.46,
  "risk_class": "very_high",
  "confidence": "medium"
}
```

## Pricing formula

The API exposes the following formula:

```text
gross_premium = max(minimum_premium, AAL × (1 + risk_margin + expense_loading + commission_loading + profit_loading + reinsurance_loading))
```

Additional commercial rules:

- `deductible = max(deductible_floor, TIV × deductible_pct[risk_class])`
- `limit = TIV × limit_pct[risk_class]`
- confidence adds a small surcharge to the risk margin

## Quote output

A quote response includes:

- `tiv_kes`
- `expected_annual_loss_kes`
- `risk_class`
- `confidence`
- `technical_premium_kes`
- `risk_margin_rate`
- `expense_loading_rate`
- `commission_loading_rate`
- `profit_loading_rate`
- `reinsurance_loading_rate`
- `loading_premium_kes`
- `gross_premium_kes`
- `quoted_rate_pct_tiv`
- `deductible_kes`
- `suggested_limit_kes`
- `formula`
- `assumptions`

## Team integration notes

The dashboard team can call:

1. `GET /buildings` to list the portfolio
2. `GET /quote/<building_id>` to show a quote for one stored building
3. `POST /quote` to quote by building name (geocoded) or by manual pricing inputs
4. `GET /formula` to display the commercial pricing logic
5. `GET /portfolio-summary` for portfolio-level reporting

## Important note

The model provides technical pricing support and a transparent commercial quote structure.
Final underwriting approval should still be made by the underwriter.
